# Hardware Test Procedure — CDJ-2000NXS2

Use a **spare, expendable USB drive**. Do not use any drive that contains a
performance library or data you cannot afford to lose.

Format: FAT32, MBR partition table. Not exFAT; not APFS; not HFS+.

---

## Acceptance levels (tested independently)

**Level A — Library and playback:**
The CDJ recognises the library, shows the playlist, loads all tracks, and
audio plays correctly. No waveform or BPM grid expected. This level is
achievable with or without analysis.

**Level B — Exported BPM grid:**
The CDJ displays the BPM value and a beat grid that was generated by this
tool (not calculated by the CDJ). Grid alignment on real music is expected
to be approximate without downbeat detection.
*This level requires real music — test sine waves have no musical beat.*

**Level C — Waveform:**
The CDJ displays a waveform. **Not implemented.** Expected result: blank or
grey waveform bar. Record what is shown but do not treat it as a pass/fail.

## CDJ-2000NXS2 test procedure

Insert the USB into the top USB slot (slot A). Wait for the CDJ to mount it.

### Level A — Library and playback

- [ ] CDJ shows REKTEST USB in the media source list
- [ ] No "Cannot read USB" or "Unsupported format" error
- [ ] Navigate to Playlist → "RekordSOS Test" is visible
- [ ] Playlist shows 3 tracks in the exported order
- [ ] Load Promo 1 → track name and artist display correctly
- [ ] Press play → audio plays without distortion or skipping
- [ ] Track duration shown matches the actual track length
- [ ] Promo 1 plays to the end (or at least 30 seconds) without error
- [ ] Repeat for Promo 2 and Promo 3

### Level B — Exported BPM grid

*Only meaningful with real music (sine waves have no musical tempo).*

- [ ] BPM value displayed (e.g. "128 BPM", not "-- BPM")
- [ ] Record the displayed BPM for each track: Promo1=___, Promo2=___, Promo3=___
- [ ] Beat grid lines visible in the CDJ display while playing
- [ ] Note whether the grid appears to align with the music's actual beat
- [ ] Note: CDJ may overwrite the grid with its own analysis — see below

**Important:** The CDJ-2000NXS2 can re-analyse a track if it does not trust
the ANLZ data. If the CDJ re-analyses and shows different BPM values, the
original ANLZ data was either missing, corrupt, or in an unacceptable format.
Record which happened: displayed our BPM value, or showed different value
after re-analysis.

### Level C — Waveform

- [ ] Record what is shown in the waveform area: blank / grey bar / actual waveform
- [ ] (Expected: no waveform — PWAV not generated)

---

## If the CDJ does not recognise the library

1. Confirm USB is FAT32 MBR (not exFAT).
2. Confirm `PIONEER/` folder is at the USB root (not inside another folder).
3. Confirm `PIONEER/rekordbox/export.pdb` exists on the USB.
4. Try slot B.
5. Power-cycle the CDJ with the USB inserted.
6. Try a different USB drive.

### Waveform observation terminology (applies to all runs)

The CDJ-2000NXS2 shows two separate waveform regions:
- **Overview** (small full-track bar, bottom of display): CDJ can compute this from audio
  itself (progressive), or display it immediately from PWAV/PWV2 in the DAT file.
- **Detail** (large scrolling waveform, centre display): CDJ does NOT compute this itself.
  It is only displayed from exported data (PWV3/PWV5/PWV4 in the EXT file).

"Progressive" always means CDJ-computed; "immediate" means from exported ANLZ.

| Display color | blue | Does NOT confirm EXT was read; CDJ own analysis is also blue |

**Level C verdict:** FAILED — waveform sections in DAT+EXT were not used by CDJ.

**Post-CDJ analysis (v4):** CDJ created ONE new ANLZ at P03A/0002FBAC (Earth n Days only).
Our ANLZ files at P9B9/00000001, P372/00000002, PD2B/00000003 were byte-identical (unchanged).
CDJ sequence counter in PDB incremented by +2. All else unchanged.

**Waveform failure investigation:**
- Both reference PDB and our PDB use sequential track IDs (1,2,3). Rekordbox writes
  main-library IDs into the analyze_path string (P00E/000254CE etc.); our generator uses
  fibonacci(track_id) = P9B9/00000001. The CDJ-generated paths (P03A, P00D) match NEITHER.
- CDJ-generated path formula: undetermined. NOT fibonacci of any known field.
  CDJ-computed lo=195500 (Earth n Days) and lo=1523 (Snoop Dogg) match no track field or
  filename hash tested (CRC32, file_size, duration, tempo, n_frames, file_size>>N).
- Leading hypothesis: CDJ assigns its own internal track IDs keyed by audio fingerprint
  and creates ANLZ at those CDJ-internal paths, possibly IGNORING the PDB's analyze_path
  for waveform display. The analyze_path may only be used for playback-only fallback.
